# Nhận xét implementation — 9 October 2026

Source: the **Nhận xét** tab in the Mộc Bàm website brief. A fresh source read on 10 October found 28 embedded reference screenshots; all were inspected. The other brief tabs are not copied into the repository.

## Delivered

- Admin catalog: edit, duplicate as a draft, guarded deletion, text/category/visibility/stock filters, low-stock indicators, sold counts, and real priced variants with atomic inventory. Optimistic revision checks prevent stale edits from undoing new orders.
- Orders/customers: readable existing MB order codes, exact customer-history links, payment reconciliation, returned status, refund recording, and an explicit decision to restock only saleable returned goods. Damaged returns can be refunded without restocking.
- Promotions: shop-wide, selected-product, and private customer vouchers; fixed or percentage reductions; usage counts and type/status filters; scheduled activation; expired-create validation; searchable recipient/product selection, voucher-name/code search and editable in-app emails with selected recipients, delivery history and duplicate-send protection. Eligibility and discounts are enforced in checkout SQL, including variants. Live delivery requires the website SMTP credentials.
- Finance: Vietnam calendar periods, refresh, charts/tables/top products, GMV, merchandise net revenue, cancellations/returns/discounts/shipping, paid completed-order AOV, payment breakdown, actual dated collections/refunds, and CSV exports even when empty. Private unit-cost snapshots and exact eligible-line discount snapshots support gross profit. Missing historical costs/allocation remain unknown rather than invented. Damaged-return costs remain expenses; saleable restocked returns reverse inventory cost.
- Traffic: separate GA4 reporting with pages/session, successful-order conversion, daily user area charts, source bars, landing bounce/revenue, devices, realtime activity, and a five-step sequential funnel from visit to successful purchase. Paid-and-completed orders feed a durable consent-aware purchase/refund outbox; accepted unpaid orders remain order submissions. Admin-only server calls use read-only Google credentials; disconnected/error states never display fabricated traffic. CSV export is available.
- Content: grouped searchable editors for homepage/about/policies, seven revised policies, post cover/video/inline media upload/change/removal, and public media access only for published references.
- Storefront: home navigation, accessible hover/keyboard/mobile policy menus, one selected policy at a time, the MỘC BÀM name and requested tagline, selected variants throughout cart/checkout, and estimated shipping labels until an address is known.
- Support: signed-in customers can send persistent messages directly to staff without a second handoff form. Staff can search, see customer/order context, reply, and resolve threads. Contact-form inquiries also have an editable direct email composer, durable delivery history and duplicate-send protection. Message ownership is enforced in SQL; reads paginate beyond Supabase's default cap and stale polls cannot erase acknowledged messages.
- Shipping/settings: road-kilometre bands with Google Routes, a dispatch address, server-bound expiring quotes, plus province/ward delivery zones and an editable fallback fee. The server validates and snapshots the fee. Overview and settings now provide search controls. Transfer availability and account completeness are visible in settings.

## Deliberate decisions and prerequisites

- Kilometre pricing is implemented with Google Routes. Activation requires a server API key, the actual dispatch address and the shop’s fee bands. Existing province/ward fees continue until it is configured. See `DISTANCE-SHIPPING.md`.
- Use a clear seven-day return policy rather than conflicting seven-day/48-hour cutoffs or mandatory unboxing video as the only accepted evidence. Distinguish damaged returns from saleable stock.
- Privacy acknowledges necessary hosting/authentication/delivery providers. Terms claim rights only in Mộc Bàm's own content and respect third-party/open-source licences.
- Voucher email now has an in-app composer and explicit send action. Gmail SMTP already exists in Supabase Auth, but its password is hidden and Vercel has no SMTP configuration. See `VOUCHER-EMAIL.md`; no real customers were emailed during tests.
- Bank transfer requires complete actual bank details. Live acceptance confirmed the shop's saved receiving details and enabled transfer option; the release does not invent them.
- Live traffic requires `GA_PROPERTY_ID` plus a Google reporting service account (Viewer access to the GA4 property and the Analytics Data API enabled). Set `GA_SERVICE_ACCOUNT_EMAIL` and `GA_SERVICE_ACCOUNT_PRIVATE_KEY` only in server environment settings. The short-lived `GA_ACCESS_TOKEN` fallback is also supported. No Google credentials are committed. Operating/ad/carrier expenses are not available, so net profit and ROAS are not fabricated.
- Enter product cost before future sales to populate new immutable snapshots. Existing orders are not backfilled from today's costs.

### Remaining prerequisites and evidence limits

- GA4 collection is configured and delivery was verified earlier. Admin reporting separately requires `GA_PROPERTY_ID` and read access through a service account (or short-lived access token). This audit did not establish a current successful production reporting response. The missing chart/metric features from the baseline audit are now implemented; reporting activation still needs credentials.
- New cost snapshots need product costs entered before sale. Today's costs cannot establish historical costs; actual carrier/ad/operating expenses need their own records.
- The most recent release passed 233 unit/API/database tests, a production build and scoped lint. Admin live QA recorded 34 distinct checks; customer QA additionally used native Chrome for checkout, vouchers, receipts and order history. Both cleanup manifests confirm fixture deletion. These results do not cover the missing features in this audit.
- Earlier policy wording decisions (one seven-day return window, unboxing media encouraged rather than mandatory, accurate service-provider/licence wording) remain documented above. They are separate from the implementation omissions.
